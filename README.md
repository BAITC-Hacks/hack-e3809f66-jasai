# TASK FORGE · Кузница задач

**Сильные идеи. Закалённые задачи. Ваша команда.**

В TASK FORGE бизнес-задача — артефакт: уточнения разогревают металл, подтверждённые сведения усиливают ядро, а студенческие команды предлагают подписанные контракты. За этой метафорой работает обычный проверяемый процесс: описание → вопросы → карточка → рейтинг → публикация → предложение → ручное решение заказчика.

Веб-MVP для AI Sana. Основная аудитория — малый бизнес, самозанятые и студенческие команды. Заказчику не нужно уметь писать техническое задание: достаточно описать проблему своими словами. Для жюри предусмотрены учебные данные и переключение ролей без регистрации.

> Это локальная демонстрационная мастерская: все посетители имеют доступ к общим демо-данным, включая управление задачами. Переключатель роли не является авторизацией. Используйте синтетические сведения.

## Быстрый старт

Нужны Node.js 22.12+ (проверено на 24.15), npm и возможность записывать файлы в каталог проекта.

Bash:

```bash
npm i && cp .env.example .env && npm run dev
```

Windows PowerShell:

```powershell
npm.cmd install
Copy-Item .env.example .env
npm.cmd run dev
```

Откройте **http://127.0.0.1:3000**. По умолчанию сервер слушает только локальный интерфейс. Ключ OpenAI не нужен: работает обозначенная в интерфейсе эвристика.

```bash
npm run seed       # создаёт данные, только если data/db.json отсутствует
npm run test       # модульные тесты
npm run typecheck  # TypeScript strict
npm run build      # производственная сборка
npm run start      # запуск собранного приложения
```

Не заменяйте существующий .env при повторной настройке. В PowerShell при блокировке npm.ps1 используйте npm.cmd для всех команд.

## Пользовательский сценарий

1. Бизнес открывает **Кузницу** и описывает проблему.
2. Кнопка **Ковать задачу** запускает анализ. Помощник возвращает четыре уточняющих вопроса в локальном режиме.
3. Заказчик вводит ответы и отдельно подтверждает достоверность каждого поля. Неизвестное можно оставить пустым.
4. **Собрать карточку** открывает все девять содержательных полей и название. Можно исправить текст вручную.
5. Отдельный флажок подтверждает разрешение на публикацию. Даже низкий рейтинг не запрещает опубликовать задачу.
6. Студент выбирает задачу в списке, на карте или через компас и отправляет стратегию, план, срок, ссылку и подпись.
7. Бизнес открывает **Мои сплавы → Управлять**, разворачивает свиток и вручную одобряет или отклоняет его.
8. Студент видит решение в **Контрактах**. Одобрение переводит задачу в работу, но не закрывает её для других откликов.

## Технологии и архитектура

Next.js **14.2.35** (App Router), React 18, TypeScript strict, Framer Motion, Tailwind CSS и собственный CSS, Zustand persist, Zod, OpenAI SDK / Responses API, Vitest, Playwright. База данных и сторонний UI-kit не используются.

Браузер → route handlers → Zod → операции с JSON → актуальный снимок Zustand. Черновик и настройки сохраняются в localStorage; опубликованные задачи и контракты — на сервере. Сервер является источником истины: после мутации клиент обновляет снимок, дополнительно синхронизируется каждые 15 секунд и при возврате фокуса.

Изменения JSON сериализуются блокировкой файла и записываются через временный файл с атомарным переименованием. Номер revision защищает карточку от перезаписи устаревшим редактором. DELETE не удаляет задачу с контрактами. При повреждённом JSON приложение сообщает об ошибке, а не пересоздаёт данные молча.

## Формула рейтинга

| Критерий               |     Вес | Нужные поля           |
| ---------------------- | ------: | --------------------- |
| Контекст и потребность |      20 | context + need        |
| Данные                 |      20 | data                  |
| Ожидаемый результат    |      15 | result                |
| Критерии успеха        |      15 | success               |
| Ограничения            |      10 | constraints           |
| Пользователи           |      10 | users                 |
| Связь с бизнесом       |      10 | contact + interaction |
| **Всего**              | **100** |                       |

```text
score = 0
для каждого критерия:
    если все его поля содержат осмысленный текст
    и все эти поля подтверждены заказчиком:
        score += вес критерия
```

В MVP «осмысленный» означает минимум три символа после trim и отсутствие известных заглушек: «не знаю», «нет», «пока не знаю», «---». Это формальная проверка, а не семантическая оценка качества.

Примеры: контекст + потребность = 20; добавить данные и пользователей = 50; добавить ограничения, результат и критерии успеха = 90; контакт + формат взаимодействия = 100. Удаление данных из полной карточки снижает рейтинг до 80. Редактирование снимает подтверждение поля; баллы возвращаются после повторного подтверждения. Сервер пересчитывает итог и не принимает присланный клиентом score.

Уровни: **0–39** — требует уточнения; **40–69** — рабочая; **70–89** — готовая; **90–100** — приоритетная. Визуальное предварительное начисление в редакторе становится серверным рейтингом после сохранения.

Числа 15 → 45 → 65 → 80 из исходного творческого промпта не воспроизводятся искусственно: интерфейс всегда использует эту формулу.

## AI: промпты, fallback и границы достоверности

По умолчанию внешний AI выключен. Для его включения задайте в .env:

```dotenv
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=доступная_вашему_проекту_модель_Responses_API
```

Модель должна поддерживать текстовый JSON-ответ. Затем перезапустите сервер и включите согласие на передачу данных в кузнице. Ключ остаётся на сервере; конкретная модель не навязывается.

- Analyze генерирует вопросы по пробелам.
- Build переносит сведения в карточку только точными цитатами из исходного ввода.
- Zod проверяет структуру и допустимые поля; groundedCard дополнительно проверяет происхождение текста.
- Заполненные пользователем поля не заменяются ответом модели.
- Таймаут, некорректный JSON, неподтверждённая цитата или недоступность API переключают на обозначенную эвристику.
- Локальный режим задаёт шаблонные вопросы с учётом темы оттока/заказов, но не является языковой моделью.
- Результат всегда редактируется и подтверждается человеком.

Zod сам по себе не предотвращает выдумки. Проверка цитат ограничивает новые факты, но не гарантирует правильную интерпретацию исходного текста. Полные примеры: [data/prompts.md](data/prompts.md). API реализован по [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/text). Реальные платные вызовы не требуются для локальной демонстрации и без настроенного ключа не проверяются.

## Правила каталога и компаса

**List:** все опубликованные задачи, по убыванию рейтинга; при равенстве — более новые по createdAt. Поиск учитывает название, потребность и теги. Фильтры по сфере и уровню можно сбросить. Неопубликованные карточки отсутствуют в каталоге, но доступны в общей демо-мастерской.

**Map:** тот же отфильтрованный набор. По Y — готовность, по X — эвристика сложности ограничений: базовые 20, +35 за упоминание API/интеграции/CRM/ML/модели, +15 за указание срока, +20 за длинное описание, максимум 95. Небольшое смещение помогает разнести совпадающие координаты. Размер звезды связан с указанным бюджетом; отсутствие бюджета не снижает рейтинг. Предпросмотр доступен при наведении и фокусе, клик открывает карточку.

**Компас:** опубликованные задачи от 40 баллов, +30 релевантности за совпавший тег навыка/технологии и +25 за сферу интересов. При равенстве выше готовность. До пяти точек, ближе к центру — больше совпадений; первоначальная стрелка направлена на лучшую рекомендацию. Выбор точки показывает её объяснение. Каталог остаётся открытым для всех.

## Данные и интеграции

В сид включены **5 черновиков, 5 задач, 5 команд и 5 контрактов**. Все организации, контакты и предложения синтетические. Ссылка example.com показывает формат ссылки на прототип, а не реальный работающий прототип.

Задачи охватывают Retail, FoodTech, EdTech и услуги с готовностью 20, 55, 70, 90 и 100. Профили содержат интересы, навыки и технологии. Реальных персональных данных нет.

Внешние источники: опциональный OpenAI API; Google Fonts для Space Grotesk, Inter Tight, JetBrains Mono и Caveat. При недоступности шрифтов используются системные. Изображения интерфейса созданы SVG/CSS/canvas; скачивание графических ассетов не требуется.

## Пять приёмочных сценариев

1. **Кузница и публикация.** Слабое описание → четыре вопроса → ответы → подтверждения → рост рейтинга → публикация → задача видна в List и Map.
2. **Честный рейтинг.** У полной карточки удалить данные → 80, восстановить без подтверждения → 80, подтвердить и сохранить → 100. «Пока не знаю» не даёт баллы.
3. **Открытый выбор.** На задачу с 20 баллами отправить два контракта разными командами. Бизнес может одобрить оба, отклонить оба или оставить без решения. Рейтинг не ограничивает отклики.
4. **Подпись и устойчивость.** Нарисовать подпись, отправить контракт, перезагрузить страницу, скачать SVG. Одобрить контракт и подтвердить этап: +10 XP только один раз.
5. **Ошибки и доступность.** Без ключа пройти сценарий; невалидный ответ AI должен вести в fallback. Проверить пустые поля, URL, неизвестную задачу, устаревшую revision, клавиатуру и prefers-reduced-motion.

Автоматические проверки:

```bash
npm test
npm run typecheck
npm run build
# В отдельном терминале должен работать npm run dev:
npm run test:e2e
```

Playwright использует установленный Google Chrome (channel: chrome). Если его нет, установите Chrome или настройте другой установленный канал в playwright.config.ts. Тестовый браузер работает в фоне. Скриншоты и trace при ошибке сохраняются в artifacts/. Тест создаёт отдельную задачу и удаляет только собственные записи после выполнения.

## Ограничения MVP

- Нет регистрации, изоляции пользователей и разграничения прав. API /state раскрывает всю **учебную** мастерскую, включая черновики. Не используйте для реальных закрытых задач.
- Next.js 14 сохранён по условию промпта. npm audit выявляет критические уязвимости этой ветки; перед публичным размещением нужна миграция на исправленную поддерживаемую версию. Локальный bind снижает доступность сервера извне, но не исправляет зависимость.
- Файловое хранилище рассчитано на один локальный экземпляр с постоянным диском, не на serverless, несколько машин или высокую нагрузку. После аварийного завершения может остаться data/db.json.lock: удалять его допустимо только после остановки сервера и проверки отсутствия активной записи.
- AI может не поддерживать выбранную модель или формат; тогда используется эвристика. Платная интеграция требует ключа и отдельной проверки.
- Подпись и печать — элементы демо, не электронная подпись и не юридическая оферта.
- Реализован один подтверждаемый этап на контракт, а не полноценный проектный трекер.
- Нет чата, платежей, файлового хранилища, уведомлений, собственного ML и автоматического назначения команд.
- Нет полноценной мобильной оптимизации, казахской локализации, исследования доступности и проверки экранными дикторами.
- Семантическая правдивость ответов остаётся ответственностью подтверждающего человека; рейтинг измеряет полноту, не надёжность бизнеса.
- Бюджет и теги поддерживаются схемой данных; в кузнице теги задаются по отрасли, поле бюджета в форме не добавлено.

## Развёрнутая версия

Публичная deployed-версия отсутствует. **http://127.0.0.1:3000** — только локальный адрес. Для размещения понадобятся обновлённый фреймворк, авторизация, права на данные и постоянное хранилище.
